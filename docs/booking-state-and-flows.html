1. Core Philosophy

  • Marketplace-driven — Venues and users transact via platform
  • Payment-priority — Confirmed = paid; no pending confirmations
  • Real-time — Slot availability and pricing reflect live state
  • Fair refund — Tiered policy based on cancellation time
  • Transparent — Price breakdown, GST, refund rules visible
  • Premium — Quality experience; no hidden fees

Booking State Machine

3. Instant Booking (3-tap)

  1. Select slot — Tap date + time slot on venue screen
  2. Confirm & pay — Summary + Razorpay Checkout in one step
  3. Done — Confirmation screen with booking ID

No multi-step forms; minimal friction to convert.

4. Multi-Court (groupId)

  • Atomic creation — Multiple slots booked as a single groupId; all-or-nothing
  • Unified payment — One order for all courts; single transaction
  • Conflict resolution — If any slot becomes unavailable, entire group fails or is retried
  • Linked cancellation — Cancelling one court in a group may cancel all (or apply policy per-slot depending on config)

BullMQ refund worker flow: On cancellation request → compute refund amount → enqueue refund job → Razorpay refund API → update booking to refunded.

7. Payment Flow

  1. User confirms booking summary
  2. Frontend calls POST /api/payments/create-order
  3. API creates Razorpay order; returns orderId, amount, key
  4. Razorpay Checkout opens (modal/redirect)
  5. User pays via UPI/Card/Net Banking
  6. Razorpay returns payment_id + signature
  7. Frontend calls POST /api/payments/verify
  8. API verifies, updates booking to confirmed, creates Payment record

8. Slot Competition

≥50% rule: For split/open play slots, if one party books ≥50% of the slot, the remainder can be offered to others. Otherwise, slot remains open until threshold is met.
