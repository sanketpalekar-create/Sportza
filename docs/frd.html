1. Introduction

This document describes functional requirements for Sportza (sports venue booking & tournament platform). It is aligned with the Data Model and BRD. Requirements are grouped by module and expressed as capabilities and API behaviour.

2. Actors

ActorDescription
User (unauthenticated)Can view public info (e.g. sports list, venue list, leaderboard)
User (authenticated)Logged-in user; role can be player, venue_owner, trainer, or admin
PlayerBooks slots, creates/joins open plays, creates/plays matches and tournaments, views stats
Venue ownerCreates/updates venues, views bookings for their venues
TrainerCreates batches, manages players, records attendance, tracks payments, posts announcements, manages profile
AdminFull access; can manage sports, venues, and users

3. Authentication and Authorization

IDRequirementPriority
FR-AUTH-1Users register/login via Auth0 (Google SSO, Email OTP via Redis, Magic Link). Auth0 JWT used for API auth.Must
FR-AUTH-2Role-based access: player, venue_owner, trainer, admin. Endpoints enforce role where needed.Must
FR-AUTH-3Venue owner can only modify their own venues; trainer only their batches; tournament creator only their tournament.Must

4. Sports and Venues

IDRequirementPriority
FR-SPORT-1List active sports (formats, default pricing, stat fields). Create/update sport (admin).Must
FR-SPORT-2Venue has multiple sport facilities; each facility can support multiple sports. Conflict check is per facility and time.Must
FR-VENUE-1CRUD venues (venue_owner/admin). Set sportFacilities (including optional surfaceType), sportRates, location, gstRate, availability.Must
FR-VENUE-2Venue can define add-ons (beverage, equipment_rent, eatable, other) with name, category, price, unit.Must
FR-VENUE-3List venues with filters; GET venue with averageRating, reviewCount; reviews API: GET/POST/DELETE.Must
FR-VENUE-4Venue has commissionPercent (0–100); set at onboarding; used for platform commission and venue net payout.Must

5. Booking and Payments

Booking: Create single or multi-court booking; full/split payment; add-ons (attributed to purchaser in split); commission on base only; refund policy: manual 95%, conflict 100%.

IDRequirementPriority
FR-BOOK-1Create booking: venue, facilityId, facilityName, sport, date, time; optional batch for discount.Must
FR-BOOK-1aMulti-court booking: multiple facilities, grouped bookings atomically (groupId).Must
FR-BOOK-2Payment type full (one payer) or split (N participants); split amounts must sum to totalAmount.Must
FR-BOOK-3Add-on purchase: POST add-on; purchaser = current user; increases total and purchaser's share.Must
FR-BOOK-5Commission on base only; add-ons increase totalAmount and venueNetAmount; platformCommissionAmount unchanged.Must
FR-PAY-1Create payment order; verify and capture; Razorpay for all payments.Must
FR-PAY-3Payment methods: UPI, Card, Net Banking via Razorpay Checkout.Must
FR-PAY-4Refunds: manual → 95% refund (5% fee); conflict → 100% refund.Must

6. Open Play

IDRequirementPriority
FR-OP-1Create open play from existing booking (pending/confirmed); provide formatName.Must
FR-OP-2List open plays (filter venue, sport, date, status); get single.Must
FR-OP-3Join/leave open play (auth). Creator cannot leave if others remain.Must
FR-OP-4Confirmation is payment-priority: first to reach ≥50% paid wins; others → cancelled_conflict (100% refund). No auto-cancel at T-30.Must
FR-OP-5Scheduled job or GET process-confirmations for confirmation logic.Must

7. Matches and Scoring

IDRequirementPriority
FR-MATCH-1Create match from booking or tournament; optional fixtureId.Must
FR-MATCH-3Update scores by scoreType: simple, cricket, tennis, padel, pickleball_rally, pickleball_service.Must
FR-MATCH-4Complete match: aggregate player stats; update fixture if tournament.Must
FR-MATCH-6Real-time scoring: Socket.io room match:<matchId>; match:score, match:status.Must

8. Tournaments

IDRequirementPriority
FR-TOUR-1Create tournament: name, sport, format (knockout, round_robin, etc.), venue or location, maxTeams.Must
FR-TOUR-2Register teams: PUT teams with { name, players[] }.Must
FR-TOUR-3Generate fixtures: POST generate-fixtures; knockout requires power of 2.Must
FR-TOUR-9Standings API: format-specific (points table, bracket, group standings).Must
FR-TOUR-10Tournament discoverability: browse, search, status filters.Must
