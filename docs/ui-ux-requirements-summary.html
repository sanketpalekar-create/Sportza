1. Philosophy & Goals

AreaRequirement
BookingCore revenue; must be fast and frictionless
Open Play + StatsRetention drivers; accessible in 1–2 taps
User typesPlayer, Trainer, Venue Owner — each gets relevant flows
Flow feelMobile-first; minimal taps; clear CTAs
TrustTransparent pricing; clear confirmation; receipts
Booking engine toneClean, professional, fast — not cluttered

2. Navigation

Single 5-tab BottomNav: Home, Venues, Matches, Train, Profile. Role-specific routes for trainers (/trainer/*) and venue owners (/venue-owner/*).

When to hide nav: Login, registration, payment modal, full-screen booking confirmation.

Secondary Patterns

  • Stack — Standard push/pop
  • Modal — Quick actions, filters
  • Full-screen — Payment, confirmation

UX Behavior Rules

  • Max 3 taps to book
  • Logical back navigation
  • No deep nesting >4 levels
  • Stats in 1 tap from Train tab

3. Booking Flow

Flow Structure

Home → Venue → Slot → Summary → Payment → Confirmation

Screens

  • Venue Detail — Facilities, courts, pricing, availability
  • Time Slot — Calendar + slot grid; multi-court selection
  • Booking Summary — Slots, price breakdown, GST
  • Payment Type — UPI / Card / Net Banking
  • Payment — Razorpay Checkout integration
  • Confirmation — Booking ID, receipt, next steps

4. Real-time & Feedback

  • Real-time updates: Slot availability refreshes; competitor notifications
  • Instant price updates: Surge/day-based pricing shown immediately
  • Error handling: Clear messages; retry options; fallback UI
