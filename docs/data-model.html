5. InstantBook & Slots

Slot is the reservable resource. Each slot belongs to a Facility and has a start/end time. Bookings reference a slot.

FacilityPricingRule types define pricing logic: peak/off-peak, weekday/weekend, flat rate, per-hour, etc.

6. Open Play

OpenPlay links to a Booking (unique relationship). Open play sessions are created from bookings.

OpenPlayPlayer is the join table between OpenPlay and User (players). Tracks participation in open play sessions.

7. Match & Stats

Match represents a game or competition. MatchEvent records events during a match (goals, fouls, etc.).

PlayerStats aggregates player performance. Stats are derived from Match, Activity, and Participation data.

8. Training Lifecycle

Batch → BatchSession → SessionAttendance

Trainers create Batches; each Batch has multiple BatchSessions. SessionAttendance tracks which members attended each session.

Pairing flow

sequenceDiagram participant VO as VenueOwner participant API as ApiServer participant TV as TvBrowser participant Phone as ScorerPhone VO->>API: POST /displays/:id/pair API-->>VO: token expiresAt displayUrl TV->>API: GET /display/pair/token TV->>API: SocketIO pairing join token Phone->>API: POST /displays/claim/token matchId API->>API: mark claimed set currentMatchId API-->>TV: SocketIO display paired matchId TV->>TV: navigate to scoreboard/matchId

Old unclaimed sessions for the same court are expired immediately when a new one is generated. The TV browser navigates once to the scoreboard on receiving display:paired — no polling or continuous refresh required.

Route: GET /venue-owner/displays — venue owner court management. Route: /display/pair/:token — TV fullscreen pairing page. Route: /claim/:token — phone claim page (auth required).
